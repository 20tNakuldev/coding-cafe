9. The four steps of the loop I just did twice are:
	Status (git status): Checking the current state of your files to see what is modified or untracked.
	Stage (git add): Moving the files you want to save into the staging area.
	Commit (git commit): Permanently saving those staged changes into the repository's history.
	Log (git log): Reviewing the commit history to verify your changes were saved successfully.

GitHub is specifically programmed to look for a file named README.md in the main folder of any repository. 13. The git push command only copies my existing local commits to the remote GitHub server. My local commits, their order, and their unique short hashes remain exactly the same. The only thing that changes is that Git updates its hidden bookmark for origin/main to show that the remote server is now fully caught up with your local machine.
14. A private repository actually exists on GitHub's remote servers. It serves as a secure backup for your code and has a URL, allowing you to explicitly grant access to specific individuals (like your TAs or project partners) while keeping it completely hidden from the general public.
If a repository does not exist on GitHub at all, it lives exclusively on your local computer's hard drive. There is no remote backup if your computer crashes, no shareable link, and absolutely no way for anyone else to view or collaborate on your code over the internet.
